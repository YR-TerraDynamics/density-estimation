Solution for Interpolation and Density Estimation

Interpolation

Data

The airquality dataset (luftqualitaet.gpkg) that I need to use for this task contains measurements of nitrogen dioxide NO₂ from 2015 for 97 monitoring sites in Switzerland. Nitrogen dioxide is produced when fuels and combustibles are burned, especially at high combustion temperatures, with road traffic being the main source.

Load required libraries

For this taks I need several R packages. The sf package is used for spatial vector data, gstat performs interpolation, and terra helps me work with raster data. I also use ggplot2 for visualization.

library(sf)
library(gstat)
library(terra)
library(ggplot2)
library(dplyr)

Create prediction grid

I use interpolation to estimate values in places where I have no measurements. To do this, I create a regular grid over the study area using st_make_grid().

The function st_make_grid() creates a regular grid over the study area. The argument cellsize = 2000 defines the spatial resolution of the grid, meaning each grid cell represents an area of approximately 2000 meters by 2000 meters (assuming the coordinate system is in meters, which the projection: “CH1903+ / LV95” is). The option what = “centers” returns only the center points of each grid cell instead of full polygons, which is useful when I want to predict values at specific locations for interpolations.

Each grid cell represents a location where I will predict NO₂.

# Create prediction grid
grid <- st_make_grid(air, cellsize = 2000, what = "centers")

# Convert to sf object
grid_sf <- st_sf(geometry = grid)

Apply Inverse Distance Weighting (IDW) interpolation

Inverse Distance Weighting assumes:

Points closer to a measurement location have more influence than distant points.

I use gstat::idw() with:

  • formula = value ~ 1: interpolate NO₂ values
  • locations = air: measurement points
  • newdata = grid_sf: prediction locations

In idw(), the formula value ~ 1 specifies that we want to interpolate the variable value (here, NO₂ concentrations) without using any additional explanatory variables. The ~ 1 means that only a constant mean is assumed across space, so the method relies entirely on the spatial weighting of nearby observations rather than on predictors.

I also test different parameters:

idp = strength of distance decay maxdist = maximum influence distance nmax / nmin = number of points used

# IDW interpolation
idw_result <- idw(
  formula = value ~ 1,
  locations = air,
  newdata = grid_sf,
  idp = 2,
  maxdist = 50000,
  nmax = 15
)
[inverse distance weighted interpolation]

Convert interpolation result to raster

Raster format in this case is better for visualization and spatial analysis. I convert the predicted values into a raster using terra::rast().

# Convert sf to SpatVector format
idw_vect <- vect(idw_result)

# Create raster from interpolation results
r <- rasterize(idw_vect, rast(grid_sf, resolution = 2000), field = "var1.pred")

Visualize the interpolated NO₂ surface

I plot the raster to see spatial patterns in air pollution. Higher values indicate higher NO₂ concentration.

df <- as.data.frame(r, xy = TRUE)

My thoughts

After experimenting with several parameter combinations, I found that a grid cell size of 500 m produced very detailed results but also introduced unnecessary local variation and increased computation time. A cell size of 10 km was too coarse and removed important spatial structures, especially around urban regions and transport corridors. In my opinion, 5 km created a reasonable balance, while 2 km provided the best compromise between spatial detail and readability. For the inverse distance weighting power (idp), I found that a value of 2 produced the most realistic spatial pattern. It created visible transitions between urban centers and more rural or alpine regions without generating overly large and uniform prediction areas in regions with sparse measurements. Regarding the maximum interpolation distance (maxdist), I observed that 40 km was necessary to avoid large gaps between measurement stations, while 50 km created smoother overlaps and more plausible predictions in sparsely sampled areas. Finally, I considered nmax = 15 to be a good choice, because lower values such as 5 or 10 often produced unstable or more clearly defined spatial boundaries. I am aware that these parameter choices are partly subjective and influenced by my understanding of Switzerland’s spatial structure, including major north–south and east–west traffic corridors, as well as mountain and lake regions with lower population density. I also noticed that the sensor network appears to be biased toward urban areas and is not evenly distributed across the country. Therefore, I selected the interpolation parameters in a way that attempts to compensate for these limitations and produce a more spatially coherent interpolation result.

In the resulting interpolation map, I can clearly identify major Swiss urban centers such as Basel, Bern, Zürich and Winterthur, Luzern, Bellinzona, Lugano, Chiasso/Como, Lausanne, Geneva, and St. Gallen. To a lesser extent, the map also reveals the main north–south and east–west transportation corridors, especially where these routes intersect in the Aarau–Olten–Zofingen region. The highest NO₂ concentrations appear to occur in the densely populated and industrialized area between Bern, Basel, Luzern, and St. Gallen, as well as around Lake Zürich. Additional urban hotspots such as Neuchâtel, La Chaux-de-Fonds, and Sion are also visible in the interpolation.

In Ticino, the interpolation shows comparatively high NO₂ values. I believe this is partly influenced by the larger distances between measurement stations, which causes urban centers such as Lugano, Bellinzona, and Chiasso to exert stronger influence over wider areas. However, there are also plausible real-world explanations for elevated concentrations in this region. Ticino forms one of the main north–south transit corridors through the Alps, concentrating large volumes of passenger and freight traffic because only few alternative routes exist. In addition, the topography of narrow alpine valleys with steep surrounding slopes may reduce atmospheric mixing and favor the accumulation of pollutants. The region is also located close to Northern Italy, one of Europe’s most industrialized areas, which likely contributes to transboundary air pollution. Finally, industrial activity and dense settlement patterns in the main valleys of Ticino, where habitable land is limited by mountainous terrain, may further contribute to increased NO₂ concentrations.

Nearest neighbor approach using Voronoi polygons

A alternative to IDW interpolation is the nearest neighbour approach. Instead of averaging nearby points, each location is assigned the value of its closest measurement station. This can be represented spatially using Voronoi polygons. Each polygon defines the area that is closer to one station than to any other station, so every polygon directly inherits the NO₂ value of its corresponding station.

Create Voronoi polygons

I first generate Voronoi polygons from the measurement locations using st_voronoi(). This produces a spatial object where each region represents the influence area of one station.

# Extract geometry of stations
pts <- st_geometry(air)

# Create Voronoi diagram (as sfc object)
voronoi_sfc <- st_voronoi(st_union(pts))

# Convert to sf object
voronoi_sf <- st_as_sf(st_collection_extract(voronoi_sfc))

# Clip the extent of the polygon layer
bbox <- st_as_sfc(st_bbox(air))

voronoi_sf <- st_intersection(voronoi_sf, bbox)

Attach NO₂ values to polygons

Now I transfer the measured NO₂ values from the station points to the Voronoi polygons using a spatial join. So that each polygon now contains the NO₂ value of its nearest station.

voronoi_sf <- st_join(voronoi_sf, air)

Visualize the result

I can now plot the Voronoi-based interpolation. Each polygon is colored by its assigned NO₂ value.

ggplot(voronoi_sf) +
  geom_sf(aes(fill = value)) +
  scale_fill_viridis_c() +
  labs(
    title = "Nearest Neighbour Interpolation (Voronoi)",
    fill = "NO₂"
  ) +
  theme_void()

My thoughts

This approach highlights the uneven spatial distribution of measurement stations very clearly. Smaller Voronoi polygons appear in areas with a high density of stations, which typically correspond to urban regions on the Swiss Plateau. In contrast, much larger polygons are visible in regions with sparse coverage, such as the Alps, Valais, Graubünden, and parts of Central Switzerland, where fewer monitoring stations are available. This creates a strong visual contrast between well-monitored and under-sampled regions.

In Ticino, the structure of the Voronoi map again reveals the main urban centers such as Bellinzona and Lugano through smaller, more tightly packed polygons, indicating higher station density and stronger local detail. At a broader scale, the spatial pattern also suggests the main north–south and east–west transport axes across Switzerland although not too clear. These corridors appear indirectly through polygons with higher values in a “line” from Lugano to Basel and Geneva via Lausanne, Bern to Zurich. Again meeting in the Aarau-Olten-Zofingen area.

This approach produces a visually clear and intuitive map, and it is useful for illustrating the spatial distribution and density of measurement stations. However, it is also quite simplistic for environmental interpretation. Because each location is assigned the value of its nearest station, the method creates sharp boundaries and ignores gradual spatial changes in NO₂ concentrations. It also does not account for important real-world processes such as distance decay, atmospheric transport, or topographic effects. For this reason, while the Voronoi-based nearest neighbour approach is helpful for understanding data coverage, it is not well suited for making detailed or scientifically robust conclusions about air pollution patterns.

Density Estimation

Data context

In this exercise, I work with GPS tracking data from a single red kite (Milvus milvus), which has been equipped with a transmitter as part of a long-term ecological research project by the Vogelwarte Sempach. The original dataset comes from Movebank and contains movement locations across Central Europe. For this analysis, I only use the subset of points located within Switzerland to focus on national-scale movement and space use patterns.

Loading the necessary libraries

Additionaly to the libraries used in the Interpolation task I need spatstat package.

library(spatstat)

Preparing point data for spatial analysis

Before I can calculate a kernel density estimate (KDE), I need to convert the GPS point data into a spatial point pattern object. The function density() from the spatstat package requires the data to be in ppp format, which represents spatial point patterns in a defined window.

Using the convex hull as the observation window is a simple and practical way to define the spatial extent for the kernel density estimation. It creates a polygon that tightly follows the outermost GPS points, so that the analysis area is closely aligned with the observed movement of the bird without requiring an external boundary such as the Swiss national outline. However, this still assumes that the animal could potentially use the entire area enclosed by the hull, which may slightly overestimate the true utilized space, especially in regions where movement is concentrated in specific subareas. For this reason, ecological studies would probably a more ecologically defined study boundary.

Kernel density estimation

The kernel density estimate describes areas of higher and lower usage intensity by smoothing the distribution of GPS points. The parameter sigma (bandwidth) controls how strongly points are smoothed. I will test different automatic bandwidth selection methods because according to theory each one makes different assumptions about spatial structure.

The eps parameter (pixel size) controls the resolution of the output grid. A smaller value creates a more detailed surface but increases computation time. A larger value is faster but can oversmooth spatial patterns. I try to choose a value that balances detail and performance, avoiding both overly pixelated and overly slow outputs.

After experimenting with different parameter combinations, I was not able to immediately find a satisfying result for the kernel density estimation. Because of this, I decided to first step back and directly visualize the raw GPS points to better understand their spatial structure.

ggplot(kite) +
  geom_sf(size = 0.5, alpha = 0.6) +
  theme_void() +
  labs(title = "Red Kite GPS locations")

From this plot, I could clearly identify a very dense cluster of observations in one area, while the rest of the points are more sparsely and broadly distributed. This helped me interpret why the automatic bandwidth selection was strongly influenced by the main cluster. After adjusting the parameters again with this spatial pattern in mind, I was eventually able to find a more balanced and visually meaningful combination for the density estimation.

# Bandwidth selection
sigma <- bw.scott(kite_ppp)

# Kernel density estimation
kde <- density(kite_ppp, sigma = sigma, eps = c(2000, 2000))

Converting to raster format

The output of density() is an image object (im), which I convert into a raster for easier spatial visualization and further GIS analysis.

kde_raster <- rast(kde)

Visualizing space use

The resulting density map shows areas where the red kite spends more time. Higher values indicate more frequent space use, which can be interpreted as core activity areas such as feeding or resting zones.

plot(kde_raster, main = "Kernel Density of Red Kite Movements in Switzerland")

The kernel density estimate is strongly influenced by the densest cluster of GPS points, which leads to a bandwidth selection that mainly reflects the core activity area. As a result, smaller clusters and more uniformly distributed locations are smoothed out or become less visible. This occurs because KDE uses a single global smoothing parameter, which cannot fully capture multiple spatial scales in the movement data.

Voronoi approach (Thiessen Polygons)

As an alternative to kernel density estimation, I can use Voronoi polygons to represent space use. Each polygon defines the area that is closest to one GPS point compared to all others. This creates a piecewise representation of space use that does not involve smoothing.

To create Voronoi polygons, I first need to merge all points into a single MULTIPOINT geometry.

# Combine points into MULTIPOINT
kite_union <- st_union(kite)

The Voronoi diagram partitions space based on distance to the nearest observation point. This provides a clear but simplified representation of spatial structure.

# Generate the polygons
voronoi <- st_voronoi(kite_union)
voronoi_sf <- st_as_sf(st_collection_extract(voronoi))

# Create bounding box polygon to clip the polygon layer
bbox <- st_as_sfc(st_bbox(kite))
voronoi_sf <- st_intersection(voronoi_sf, bbox)

To interpret the Voronoi map, I attach the original GPS observations to each polygon using a spatial join.

voronoi_sf <- st_join(voronoi_sf, kite)

Each polygon now represents the spatial influence of a single observation point. Areas with dense sampling appear as smaller polygons, while areas with sparse tracking data appear as large polygons.

ggplot(voronoi_sf) +
  geom_sf(show.legend = FALSE) +
  theme_void() +
  labs(title = "Space Use of the Red Kite in Switzerland with Thiessen polygons")

My thoughts

I find this Voronoi or Thiessen polygon approach to be a very intuitive way of visualizing space use, especially because it directly shows how observations are distributed across space. Before this exercise, I had not encountered Thiessen polygons in practice, but I think they provide an interesting alternative perspective compared to smooth density surfaces. While the resulting map may require some additional explanation for non-technical audiences, the concept of assigning each area to its nearest observation point is relatively easy to understand once introduced. At the same time, I also question how useful this method is in a stricter scientific context compared to kernel density estimation. KDE appears to represent spatial intensity and gradual transitions more realistically, whereas Voronoi polygons create abrupt boundaries that may oversimplify movement behaviour. Nevertheless, I think the Thiessen approach is a cool way for exploring spatial structure, observation density, and local influence zones in a visually clear and interpretable way. And if we use other variables as well, we could for example color each polygon according to the time of day the bird is there or by season. You could also color them by altitude because the bird might overfly different areas in different heights. You could also use zonal statistics and color the polygons by land use or something else to gain more insight about the geographical feature in the vicinity of the point.
